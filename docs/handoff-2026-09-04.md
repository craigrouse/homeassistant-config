## The week's incidents (2026-09-02 → 09-04) and what was changed

1. **Shadow charge (EV morning extension) never applied (09-02 morning).** `input_datetime.tesla_shadow_ready_by` was 09:15; the Octopus target-time select only has half-hour options; `select_option` threw after the charge limit had already been raised. Fix: shadow time floored to the half-hour everywhere, both writes `continue_on_error` + verified, failure pushes a phone alert.
2. **Saving session 20:00 (09-02) no export.** Controller pushed correctly; gateway ignored it (Tesla-side stall). The re-assert loop judged "stuck" by battery power, which the ~1.1 kW house load defeated. Fix: stuck tests use grid/site power; re-assert does the `self_consumption → 45 s → autonomous` toggle (the thing that reliably un-sticks the gateway); manual export toggle exits the loop.
3. **22:30 smart-slot fill (09-02) never started; manual import also stalled until its kickstart.** Root cause pattern for all three: since gateway fw 26.2 the Powerwall checks the tariff before honouring reserve/mode, and every writer pushed the tariff LAST. Fix: **tariff first, 15 s settle, then grid switch → reserve → export → mode** in all six tariff writers. New **Grid Fill Watchdog** for the fill direction (dispatch or 23:30–05:00 only, SoC < 90, 4 rounds).
4. **Session 18:00 (09-03).** Same stall; owner's manual export started it; the controller's re-assert then briefly toggled against a stale Teslemetry reading. Fix: all export stuck tests read the local gateway sensor; sessions now start **5 min early** (calendar offset −5 m, TOU spike opens at T−5, paid-session gate is a template over `joined_events` since the binary_sensor is off pre-start; redundant T+0 triggers ignored once export is flowing).
5. **Evening dump planner made non-blind (09-03/04).** Re-computed from live SoC 2 min before the planned start (later-only). **Slot-aware (09-04):** planned Octopus dispatches before 23:30 subtract slot time and add expected refill so the start moves earlier (dump → refill at 6.9p in the slot → dump again); re-plans on `planned_dispatches` attribute changes between 20:40 and 23:30, never once the dump has begun. Scheduler now **pauses the evening dump for any live dispatch** (previously only the night dump — exporting while the car drew 7.4 kW netted at the meter).
6. **Set-time-of-next-session** filter changed to `end > now()` so an in-progress session is not dropped at the first event refresh (it reset both helpers to the 2026-08-12 fallback mid-session on 09-02).

Detailed reasoning is in each automation's `description`. Verified live so far: 09-02 23:30 refill and 09-03 23:30 refill started within ~3 min of the tariff-first push with no nudge; 09-03 session export ran (with the caveat in item 4).

## Design rules now in force (also in README → Conventions)

- Tariff first, mode last, then **verify and nudge**. Never trust a pushed posture.
- Stuck tests read the **local** gateway sensors, never the Teslemetry ones.
- Toggle spacing is 45 s (`self_consumption → autonomous`); 5–10 s raced Tesla's cloud sync in the past.
- One TOU writer per situation (scheduler / session / power-hour / manual), gated by `input_boolean.manual_export_active`, `input_boolean.start_manual_force_import`, `input_boolean.power_hour_active`, `binary_sensor.octopus_paid_saving_session_active`.
- `automation.trigger` on the Daily Scheduler always with `skip_condition: false`.
- Never export during a car dispatch.
